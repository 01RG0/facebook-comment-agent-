# Facebook Comment Reply Agent — Claude Context

## Project Summary

An AI-powered SaaS that monitors comments on a connected Facebook Page and automatically sends **private replies** (DMs in response to public comments) generated by an LLM. Built for a single teacher client first, architected as multi-tenant SaaS from day one.

Owner: Ahmed | Status: Greenfield — no code written yet, plan approved, ready to implement.

---

## Approved Tech Stack

| Layer | Choice |
|---|---|
| Runtime | Node.js + TypeScript |
| Framework | Next.js 14 (App Router) |
| Database | Supabase (Postgres + Auth + RLS) |
| Queue | BullMQ + Redis |
| UI | shadcn/ui + Tailwind CSS v4 |
| Hosting | Railway (2 services: web + worker) |
| Encryption | Node built-in `crypto` AES-256-GCM |
| AI providers | Gemini (`@google/genai`), Mistral (`@mistralai/mistralai`), OpenAI-compat (`openai`) |
| Logging | pino |

## Database Schema

Tables: `profiles`, `pages`, `settings`, `comments_log`

Key design decisions:
- `pages.access_token_enc` + `pages.access_token_iv` — AES-256-GCM encrypted page access token
- `settings.ai_api_key_enc` + `settings.ai_api_key_iv` — encrypted per-user AI API key
- `comments_log.fb_comment_id` — UNIQUE constraint for dedup at DB level
- RLS on every table: users can only see their own data
- Worker uses service role key (bypasses RLS) — only process that needs cross-user access

## Critical Security Rules

1. **`ENCRYPTION_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `META_APP_SECRET`** — never in any `NEXT_PUBLIC_` var, never returned in any API response body
2. **Tokens never reach the browser** — decrypt server-side only, in API routes or the worker process
3. **Webhook signature verification** — must use `crypto.timingSafeEqual` on `X-Hub-Signature-256` before processing any event
4. **Facebook OAuth callback** — must verify `state` param (stored in cookie before redirect) to prevent CSRF
5. **All API routes** — must call `supabase.auth.getUser()` first and verify the requested `pageId` belongs to that user
6. **Service role client** — only in `src/lib/supabase/admin.ts`, only imported by the worker process

## Key Architecture Decisions

- **Webhook → Queue separation**: Meta expects < 2-3s response. The webhook endpoint only verifies + enqueues, never calls AI or Graph API directly.
- **Two-layer dedup**: BullMQ `jobId = fb_comment_id` (queue level) + `UNIQUE` constraint on `comments_log.fb_comment_id` (DB level)
- **Next.js monorepo**: Web service (dashboard + API routes) and worker process (BullMQ worker) share one codebase, deploy as two Railway services
- **Provider-agnostic AI**: `AiProvider` interface with `generateReply(comment, instructions): Promise<string>` — user selects provider per Page in dashboard
